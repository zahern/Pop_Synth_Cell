\subsection{Candidate-Pool Expansion: Per-Zone Audit}
\label{sec:pool_expansion_audit}

The candidate-pool expansion uses the per-candidate repair
\eqref{eq:mip_repair} and the default-on support block \eqref{eq:mip_joint} of
Section~\ref{sec:mip_pool_expansion}: the repair keeps as much of the real donor
profile as the structural rules allow, and the block admits a set of binary
support variables per zone that covers every sourceable zero-capacity cell while
keeping the added set's deviation from the zone's target shares small. The released defaults are a per-cell carrier requirement
$\nu_c=\lceil E_{z,k,m}/r_{\max}\rceil$, a per-zone budget
$K_z=\sum_c\nu_c$ households, coverage weight $\lambda_0=10^{5}$ and marginal
weight $\lambda_1=10^{-2}$; the marginal term is dominated by $\lambda_0$, so
opening a sourceable cell always outranks any marginal gain the added set could
buy. Coverage is soft through the slack $e_c$, so a cell that no donor can source
is reported rather than making the program infeasible.


Table~\ref{tab:pool_expansion_audit} lists every zone the audit has processed,
two per row, with the run totals and per-zone medians beneath; the board in
Figure~\ref{fig:expansion_board} counts the same run by control code. The audit is
a mechanism check under one fixed set of parameters; it establishes that the step
can make the cells a zone's slice cannot supply selectable, not that it closes any
zone's full deficit, which is a question for the zone fit and the validation
tables. Across the \ExpZones{} zones there were
\ExpZeroCells{} zero-capacity cells, of which \ExpCoveredCells{} received at least
one carrier, with a coverage set of
\ExpAddedHouseholds{} households (\ExpAddedPersons{} persons), and every support
solve returned an optimal solution. The released implementation also appends the
rest of the constructed menu, so the final pool addition is 19{,}325 households
and 67{,}475 persons (Table~\ref{tab:pool_growth}); the audit counts above
describe the coverage set, not that larger addition. The weighted joint-marginal deviation of the
\emph{added set} ranged from \ExpDevSumMin{} to \ExpDevSumMax{} per zone (median
\ExpDevSumMedian); the added set ranges from 13 to 648 persons per zone (median
167), so a single person can move a cell share substantially while the addition
remains small relative to the zone population. This figure describes the added set,
not the fitted zone population.

\emph{Which cells expansion may fill.} A cell is in scope only when its SA2 target
is positive and no record in the zone's pool slice carries it. A cell whose target
is zero is a structural zero: it must stay empty, so expansion never supplies it.
A cell with a positive target and some carriers is a partial shortfall: replication
can reach it, so it is left to the zone fitter. Targets are SA2 while donors come
from the SA4 microsample, so a cell can be required by a zone target even when the
wider sample holds no carrier; expansion sources from the SA4 sample and still
satisfies the SA2 target. A cell can therefore remain open for three reasons: no
observed record carries the category, no rule-admissible shell can host a carrier,
or the per-zone budget is exhausted. The first two occurred in this run; the third
did not.

\emph{Why the remaining cells stay open.} None of the \ExpUncoveredCells{}
uncovered cells was a selection failure. Each lies in a control code that the
extract cannot source; most are codes absent from the extract or padding codes,
and the remainder are rare categories for which no donor--shell candidate survived
the household and rule checks. Figure~\ref{fig:expansion_board}b gives the count for
each code. The residual is a property of the extract, not of the expansion, and it
is reported rather than synthesised.
